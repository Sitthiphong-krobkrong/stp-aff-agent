# stp-aff-agent — ระบบช่วยผลิตคลิป Affiliate ของ STP Picks

โปรเจกต์นี้แยกจาก `stp-aff-studio` โดยใช้ Studio เป็นข้อมูลอ้างอิงเท่านั้น

**สิ่งที่ v0.1 ทำได้:** รับข้อมูลสินค้า → จัดอันดับ → นำเข้ารูป → เขียนแผนคลิป → สร้างเสียงและวิดีโอแนวตั้ง 9:16 พร้อมข้อความภาษาไทยและไฟล์ SRT → ตรวจ QA → สร้างชุดข้อความสำหรับโพสต์ใน `post.txt` การโพสต์และปักตะกร้ายังเป็นงานของคน

**สถานะ POC (ตรวจ repo วันที่ 14 พ.ย. 2026):** มี MP4 จากการรันจริงและเพิ่ม flow `auto` ที่บังคับหลักฐานแหล่งข้อมูล/สิทธิ์สื่อ คัดสินค้าและลองตัวถัดไปเอง แต่ยังไม่มีการรันกับผู้สมัครจริงอย่างน้อย 3 รายการที่มีสิทธิ์สื่อและเสียงครบ จึงยังไม่ถือว่า POC สำเร็จ `READY_FOR_APPROVAL` หมายถึงผ่าน QA ที่ตรวจด้วยเครื่องได้เท่านั้น คนยังต้องดูคลิป ตรวจข้อเท็จจริงและอ่านขอบเขตสิทธิ์จริง

เอกสารส่งต่องานอยู่ใน [docs/](docs/) และแผน v0.1 อยู่ที่ [docs/10_PLAN_v0.1.md](docs/10_PLAN_v0.1.md) เอกสารแผนบางส่วนเป็นบันทึกจากวันที่ 11 พ.ย. 2026 ไม่ใช่ผลตรวจสถานะล่าสุด

## Flow อัตโนมัติที่กำลังทำ POC

```text
[Human] ตั้งค่าแหล่งข้อมูลที่ได้รับอนุญาต + ทะเบียนสื่อ/เสียงที่มีหลักฐานสิทธิ์ (ครั้งแรก)
    |
    v
[Bot] ค้นสินค้า >=3 รายการ -> จัดอันดับ -> ตรวจสื่อ -> ลองสินค้าถัดไปถ้าติดขัด
    |
    v
[AI: Ollama / Qwen3:8b หรือ Claude CLI] เขียนบท + วางแผนฉาก
    |
    v
[TTS ที่มีหลักฐานสิทธิ์] พากย์ไทย
    |
    v
[Bot: FFmpeg] รวมรูป + ข้อความ + เสียง -> MP4 + ซับ SRT
    |
    v
[Bot] ตรวจ QA -> ส่งคลิป/บท/หลักฐาน/รายงานให้ตรวจ หรือรายงาน BLOCKED
    |
    v
[Human] ดู/ฟัง + ตรวจข้อเท็จจริง/สิทธิ์ -> สั่งแก้ หรืออนุมัติ
    +-- สั่งแก้ -> [Bot + AI] สร้างเวอร์ชันใหม่ -> กลับมา Human review
    +-- อนุมัติ -> ส่งต่อให้โพสต์ด้วยคน (ยังไม่มีตัวโพสต์อัตโนมัติ)
```

AI เขียนบทใช้ Ollama กับ `qwen3:8b` เป็นค่าเริ่มต้น หรือเลือก Claude CLI ได้ `auto` ให้ระบบเลือกสินค้าตามอันดับ ส่วน `make` ใช้โฟลเดอร์สินค้าที่เตรียมไว้ กติกาใหม่ให้ AI เขียน hook จากคุณสมบัติสินค้าที่มีในข้อมูล และให้เขียนใหม่เมื่อเป็น hook สำเร็จรูปหรือมีคำขาย/ผลลัพธ์ที่ไม่มีหลักฐาน ห้ามพูดหรือแสดงราคาในคลิปและข้อความโพสต์ QA ตรวจรูปแบบนี้ซ้ำ แต่ยังไม่แทนการตรวจข้อเท็จจริงและความลื่นของบทด้วยคน

**Flow เป้าหมาย:** ให้บอทค้นสินค้า ตรวจข้อมูล/สิทธิ์ ผลิตคลิป และ QA จนได้แพ็กเกจพร้อมหลักฐาน จากนั้นคนเข้ามา Review และอนุมัติท้ายงานเท่านั้น หากหลักฐานไม่ครบให้บอทรายงาน `BLOCKED` ดู [แผน flow อัตโนมัติ](docs/03_AGENTS_AND_WORKFLOW.md#target-operating-flow--bot-prepares-human-reviews-at-the-end)

## Tech stack

| Claude CLI | AI เขียนบทแทน Ollama | ตัวเลือก |

| Azure Speech | สร้างเสียงพากย์แทน Edge TTS | ตัวเลือก; ต้องตั้งค่าและตรวจสิทธิ์เสียง |

## ติดตั้งบน Mac

ต้องใช้ Python 3.11 ขึ้นไปและ FFmpeg

```bash
brew install ffmpeg python@3.12
python3.12 -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -r requirements.txt
pytest -q
```

ถ้าจะใช้ Ollama เป็นตัวเขียนแผนคลิป ให้เตรียมโมเดลด้วย `ollama pull qwen3:8b` หรือเลือก `--director claude_cli` เพื่อใช้ Claude CLI ที่ตั้งค่าไว้บนเครื่อง

## วิธีใช้งาน

### หน้า Review บน Mac

```bash
python -m agent.review_web --port 8765
```

เปิด `http://127.0.0.1:8765` เพื่อดูรายการงาน คลิป QA รูปและหลักฐานสิทธิ์, ข้อความโพสต์, เวอร์ชันก่อน และประวัติคำสั่ง หน้าเว็บสั่งแก้ด้วย Ollama/Qwen3 หรือ Claude CLI ในงานเบื้องหลังทีละงาน และให้คนยืนยันการตรวจคลิป/หลักฐานก่อนอนุมัติ ข้อมูลคำสั่งจากหน้าเว็บอยู่ใน `runs/review.sqlite3` หน้าเว็บเปิดเฉพาะเครื่องนี้และยังไม่มีระบบบัญชีผู้ใช้; ห้ามนำไปเปิด public โดยตรง

### 1. เตรียมข้อมูลสินค้าและจัดอันดับ

เลือกแหล่งข้อมูลที่ได้รับอนุญาตและตรวจสอบที่มาของไฟล์ก่อนใช้งาน ตัวอย่างคำสั่ง:

```bash
python -m agent discover --source csv --csv offers.csv
python -m agent discover --source manual --inbox inbox
python -m agent discover --file path/to/stp-offers-YYYY-MM-DD.json --top 10
```

คะแนนประกอบด้วยค่าคอมมิชชัน 35%, ยอดขาย 25%, จำนวนรูป 20%, คะแนนรีวิว 10% และราคา 10% ค่าที่ไม่ทราบจะได้คะแนน 0 ในส่วนนั้นและถูกระบุว่าไม่ทราบ ไม่สร้างค่าขึ้นมาเอง ผลการจัดอันดับบันทึกไว้ที่ `runs/discover-*.json`

โค้ดมีตัวเลือก `shopee_openapi` แต่ยังไม่มีหลักฐานว่าทดสอบกับ Open API จริง เมื่อได้รับสิทธิ์และตรวจสอบ API กับเอกสารทางการแล้ว จึงใช้ตัวแปร `SHOPEE_AFF_APP_ID` และ `SHOPEE_AFF_SECRET` กับคำสั่งนี้ได้:

```bash
python -m agent discover --source shopee_openapi --keyword "โคมไฟ"
```

### 2. สร้างคลิปจากโฟลเดอร์สินค้า

โฟลเดอร์ `inbox/<product>/` ต้องมี `product.txt` และภาพอ้างอิงสินค้าจริงอย่างน้อย 3 รูปใน `images/` พร้อม `rights.json` ที่ระบุ `origin` เป็น `operator_capture` หรือ `brand_supplied` และชี้ไฟล์หลักฐานสิทธิ์เชิงพาณิชย์สำหรับ Shopee และ TikTok ระบบไม่ดาวน์โหลดรูปหน้าร้านที่ไม่มี grant และไม่รับ URL รูปจาก Shopee CDN เป็นภาพอ้างอิง ข้อมูลที่รองรับเพิ่มเติม ได้แก่ `ลิงก์:`, `ลิงก์ affiliate:`, `ค่าคอม:`, `ขายแล้ว:` การระบุว่าเป็นรูปของตนเองหรือมีใบอนุญาตในไฟล์ข้อความอย่างเดียวไม่พอ

ถ้าภาพที่ได้รับอนุญาตมีคำโฆษณาหรือสิ่งรก ให้ทำภาพสะอาดจากไฟล์นั้นก่อน แล้วใส่ `cleaned_media_path` และ `cleaning_method` (`crop` หรือ `image_edit`) ใน grant เดียวกัน ระบบเก็บต้นฉบับไว้ใน `assets/original/` ใช้ภาพสะอาดเป็นอินพุต LTX และ QA ตรวจ hash ต้นฉบับเพื่อให้คนเทียบว่า AI ไม่เปลี่ยนหน้าตาสินค้าจริง การลบคำหรือโลโก้ในภาพไม่เปลี่ยนสิทธิ์ของต้นฉบับ

```bash
python -m agent make inbox/<product>
python -m agent make inbox/<product> --director claude_cli
python -m agent make examples/demo-lamp --plan examples/demo-lamp/plan.json
python -m agent regen runs/<id> --from plan
python -m agent revise runs/<id> --instruction "แก้บทเปิด" --avoid-phrase "คำที่ไม่ให้พูดอีก"
python -m agent decide runs/<id> approve --reviewed
python -m agent decide runs/<id> reject --note "เหตุผล"
```

คำสั่ง `make` ใช้ `ollama` และ `edge` TTS ตามค่าเริ่มต้นใน `config/agent.toml` และใช้ LTX สร้างวิดีโอจากภาพอ้างอิงที่มี grant ตั้ง `[video] ai_rights_evidence = "/absolute/path/to/model-output-terms.pdf"` ใน `config/local.toml` ด้วย ตัวอย่าง `demo-lamp` เป็น fixture สำหรับทดสอบ renderer ไม่ใช่สินค้าที่ค้นพบจริงหรือสื่อพร้อมโพสต์ `regen` ยังเลือกเริ่มใหม่จาก `voice` หรือ `render` ได้

ไฟล์ผลลัพธ์อยู่ใน `runs/<id>/out/`: `final.mp4`, `post.txt`, `final.srt`, `check.jpg`, `qa_report.json` และ `manifest.json` ถ้ามี `โค้ด Shopee` จะสร้าง `final_tt.mp4` และ `final_tt.srt` เพิ่ม หลักฐานรูปและเหตุการณ์อยู่ใน `assets/assets.json` และ `events.jsonl`

### 3. ทดลองคำสั่ง `auto`

`auto` รุ่นใหม่ต้องมีผู้สมัครอย่างน้อย 3 รายการที่มีเวลา `observed_at` จากแหล่งข้อมูลจริง, เอกสารที่มาของ CSV (ถ้าใช้ CSV), รูปอย่างน้อย 3 รูปต่อสินค้าที่มีหลักฐานสิทธิ์เชิงพาณิชย์สำหรับ Shopee และ TikTok, และหลักฐานสิทธิ์ของเสียง TTS ก่อนเริ่มผลิต ใช้ [ตัวอย่าง registry](config/rights_registry.example.json) เป็นรูปแบบข้อมูลเท่านั้น แล้วบันทึกข้อมูลจริงใน `config/rights_registry.json` (ไม่เข้า Git) ตั้งค่า `rights_evidence` ของเสียงใน `config/local.toml` เช่น:

```toml
[tts]
provider = "azure"
rights_evidence = "/absolute/path/to/voice-license-or-terms.pdf"
```

ไฟล์ CSV ต้องมีคอลัมน์ `observed_at` เป็นเวลาที่ข้อมูลสินค้าถูกสังเกตจริง ไม่ใช่เวลาที่นำไฟล์เข้าโปรแกรม หากมีคุณสมบัติจากแหล่งข้อมูลที่ได้รับอนุญาต ใส่เพิ่มใน `fact_1` ถึง `fact_5` ได้ ระบบจะส่งข้อมูลเหล่านี้ให้ AI เขียนบทโดยตรง แต่ยังต้องตรวจว่าข้อความในแหล่งข้อมูลถูกต้องก่อนอนุมัติ ตัวอย่างการรันหลังตั้งค่าและสิทธิ์พร้อม:

```bash
python -m agent auto --source csv --csv offers.csv --source-evidence /path/to/source-permission.pdf --count 1 --director claude_cli
```

`auto` จัดอันดับโดยใช้รูปที่มีหลักฐานสิทธิ์ ลองสินค้าถัดไปเมื่อสิทธิ์หรือ QA ไม่ผ่าน และหยุดเมื่อได้แพ็กเกจ `READY_FOR_APPROVAL` ครบ `--count` หรือหมดผู้สมัครภายใน `--max-candidates` ผลรวมและเหตุผลที่ข้ามแต่ละสินค้าอยู่ใน `runs/auto-*.json` ถ้าไม่ครบจะรายงาน `BLOCKED` และคืน exit code 2 คนดู/ฟังและตรวจข้อเท็จจริงกับเอกสารจริงที่ท้ายงาน หากต้องแก้ใช้ `revise` บอทจะเก็บแพ็กเกจเดิมใน `versions/v001/` และสร้างเวอร์ชันใหม่ให้ตรวจอีกครั้ง; งาน `QA_DONE` ที่ตก QA ด้วยเหตุอื่นยังสั่งแก้ได้เมื่อสิทธิ์รูป/เสียงผ่าน แต่คลิปเก่าที่ขาดหลักฐานสิทธิ์ต้องเติมหลักฐานก่อน คำที่ระบุผ่าน `--avoid-phrase` จะถูกเก็บในข้อมูลสินค้าของ run เพื่อกันกลับมาในรอบถัดไป

ใน repo ยังมี bookmarklet `python -m agent bookmarklet` สำหรับส่งออกรายการจากหน้า affiliate dashboard โดยเรียก endpoint ภายในของหน้าเว็บที่ล็อกอินอยู่ สิทธิ์การใช้ endpoint นี้ใน workflow อัตโนมัติยังไม่ได้ยืนยัน จึงต้องตรวจสอบการอนุญาตก่อนนำมาใช้เป็นแหล่งข้อมูลจริง ห้ามใช้วิธีที่ฝ่าฝืนข้อจำกัดของแพลตฟอร์ม

## เงื่อนไขก่อนนำคลิปไปใช้

- **สิทธิ์สื่อ:** [AGENTS.md](AGENTS.md) กำหนดหลักฐานสิทธิ์ของภาพอ้างอิงบนทั้ง Shopee และ TikTok รูปหน้าร้านที่ไม่มี grant จะไม่ถูกดาวน์โหลดหรือใช้สร้างวิดีโอ และ QA จะบล็อก `READY_FOR_APPROVAL` หากหลักฐานภาพ เสียง หรือโมเดลวิดีโอไม่ครบ คนยังต้องอ่านขอบเขตสิทธิ์จริงและดูว่าสินค้าที่ AI สร้างตรงรุ่นก่อนอนุมัติ
- **ข้อเท็จจริงในคลิป:** โค้ดตรวจตัวเลข คำต้องห้าม และ `ห้ามพูด` แต่ยังตรวจไม่ได้ว่าข้อความทั่วไปทุกประโยคมีหลักฐานรองรับ ต้องตรวจบทพูด ข้อความบนจอ และ caption ด้วยคน
- **เสียง:** `edge` เป็นค่าเริ่มต้น แต่สิทธิ์ใช้เสียงเชิงพาณิชย์ยังไม่ยืนยัน หากไม่มีเอกสาร `rights_evidence` QA จะบล็อก `READY_FOR_APPROVAL`; `silent` ใช้ทดสอบ renderer เท่านั้น หากใช้ `azure` ต้องตั้ง `AZURE_SPEECH_KEY` และตรวจเงื่อนไขเสียงที่เลือก
- **ภาพและจังหวะ:** QA ตรวจข้อมูลวิดีโอด้วย `ffprobe` และสร้าง `check.jpg` แต่ยังไม่ยืนยันการออกเสียง ความอ่านง่าย และการตรงกันของเสียง ซับ และภาพโดยอัตโนมัติ ต้องดูและฟังไฟล์จริง
- **การอนุมัติ:** `decide approve --reviewed` รับได้เมื่อ state เป็น `READY_FOR_APPROVAL`, QA ผ่านสิทธิ์รูป/เสียง และไฟล์แพ็กเกจครบ บันทึก hash ของไฟล์ที่อนุมัติ โปรแกรมไม่โพสต์คลิปเอง

ถ้าหาสินค้าหรือสื่อที่มีสิทธิ์ใช้ไม่ได้ ให้รายงานว่า **ติดขัด (blocked)** ไม่ถือว่าการสร้าง MP4 จาก fixture หรือรูป listing ที่ยังไม่มีหลักฐานสิทธิ์เป็น POC สำเร็จ
